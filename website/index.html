01 / Motivation & Cognitive Foundations

Why System 1? The Failure of Autoregressive LLMs for Decisions

In Thinking, Fast and Slow, Daniel Kahneman codified human cognition into two distinct operating modes:

System 1 (Intuitive & Fast)

Parallel, non-deliberative, feed-forward sensory pattern recognition. Evaluates validity, intent, and contradiction instantly in constant time without verbalizing thoughts.

System 2 (Deliberative & Slow)

Sequential, autoregressive, token-by-token generation. Solves complex multi-step algebra, writes essays, and searches minimax trees at high compute cost and latency.

The Modern AI Industry's Critical Architectural Mistake

Today, enterprise RAG verification, tool routers, and citation auditors invoke 70B autoregressive language models (System 2) just to make simple classification judgments: "Does this passage support the claim?" or "Should I invoke the search tool or calculate tool?".

Generating 50–100 tokens autoregressively for a binary or 3-way decision carries enormous overhead:

  • Severe Latency Penalty: 500 ms to 2,500 ms latency makes interactive agent loops sluggish and UI responsiveness impossible.
  • Catastrophic Inference Economics: Cloud API tariffs cost $0.0399 to $0.15 per 1,000 queries, bankrupting high-throughput pipelines.
  • Brittle Parsing & Hallucination: Models fail with markdown fences, preamble rambling ("Sure, I can help!"), or stochastic formatting drift.
  • Uncalibrated Probabilities: Softmax over generated vocabulary tokens does not represent calibrated semantic belief.

02 / Technical Architecture

Model Architecture, Pooling Head & W4A16 Engine

The Unified Multimodal Cross-Encoder Pipeline

1. Input Formatting Premise: <|vision_start|>[ViT Patches]<|vision_end|> {text}\nHypothesis: {claim}\nPrediction:
▼
2. Backbone Encoder Google Gemma 4 (e2b 35 layers / e4b 42 layers) · 128K Context Window
▼
3. Pooling Operation Flip-Argmax Last Non-Pad Token: idx = mask.sum(dim=1) - 1
▼
4. Head Projection Gemma4RMSNorm(pooled) ➔ Linear(d_model, 3) ➔ [z_con, z_ent, z_neu]
▼
5. Calibration Readout Softmax(logits / T*) ➔ Calibrated Probability Simplex Δ²

Right-Padding & Invariant Pooling: Unlike generative models where left-padding is used for autoregressive decoding, cross-encoders enforce strict right-padding (tokenizer.padding_side = "right"). Representation pooling is computed over the last non-pad token index: 

last_token_idx = attention_mask.sum(dim=1) - 1
pooled = last_hidden_state[torch.arange(batch_size), last_token_idx]
normalized = score_norm(pooled)
logits = score_head(normalized)  # Shape: (batch_size, 3)

Terminal Delimiter \nPrediction:: Appending a fixed terminal delimiter token eliminates lexical subword bias of trailing sentence characters, ensuring the pooled representation captures global semantic entailment rather than the morphology of the final period or punctuation mark.

Production W4A16 Engine

INT4 Group-32

To achieve production-grade latency on consumer GPUs (and Apple Silicon Macs), we engineered an asymmetric INT4 Group-32 quantization pipeline conforming to the Hugging Face compressed-tensors specification:

Asymmetric Group-32 Quantization 4-bit Weights

Quantizes linear weights along input channels into blocks of 32 elements. Each group maintains independent FP16 scale and INT4 offset parameters, maintaining 99.1% of full-precision classification accuracy.

Multi-Query Attention (MQA) Exclusion 16-bit Protected

Gemma 4 uses multi-query attention where Key/Value projections have only 1–2 heads. Quantizing k_proj and v_proj to INT4 causes severe precision collapse; we strictly preserve MQA projections in native 16-bit precision.

In-Place Memory Streaming 5.1 GB Resident

Instead of loading unquantized weights and quantizing in VRAM, weights stream directly from disk to GPU memory buffers, capping peak initialization VRAM at 5.1 GB (vs 12.2 GB).

03 / Algorithmic Breakthrough (OPT-01 & OPT-11)

Shared Prefix KV Caching: Sashing Multi-Option Latency by 77×

The Crisis: The POP909 & API-Bank Latency Wall

During the comprehensive 151,034-request Decision Index evaluation, we uncovered a crippling bottleneck in standard cross-encoders:

  • In POP909 (Catalog 22), 3,799 requests evaluated $K=129$ chord candidates over a 4,445-token musical history. Naive cross-encoders evaluate 129 concatenated pairs: {(\text{Premise}, \text{Option}_1), \dots, (\text{Premise}, \text{Option}_{129})}.
  • Re-encoding the identical 4,445-token premise 129 times required 9 sequential forward passes per request, inflating latency to 9,311 ms per decision.
  • POP909 alone consumed 9.8 hours—accounting for 62% of the entire benchmark suite runtime!
  • In API-Bank (Catalog 3), 53 candidate tools over a 4,096-token premise spiked latency to 16,947 ms, and caused CUDA OOM crashes when 16 items of 4K tokens (~71,000 active tokens) exceeded 32 GB VRAM on the RTX 5090.

The Insight: Causal Attention Invariance

Gemma 4 is a causal decoder transformer. Attention is strictly lower-triangular:

Premise tokens at positions 0 … L_premise ONLY attend backward to preceding premise tokens.
They NEVER attend forward to candidate hypothesis tokens.
⟹ Key & Value representations of the premise are 100% INVARIANT across all K candidates!

The Solution: Two-Stage Prefix KV Evaluation

  1. Stage 1 (Single-Pass Premise Pre-Fill): The premise is passed through the model once ($B=1, L=L_{\text{premise}}$) with use_cache=True. The KV tensors (past_key_values) are cached in ~120 ms.
  2. Stage 2 (Parallel Candidate Suffix Forward): The cached KV tensors are repeated across the batch dimension. All $K$ short candidate suffixes ($L_{\text{hyp}} \approx 15\text{--}30$ tokens) are forward-passed in parallel. Total active tokens drop from 573,000 to just 2,580 tokens (<200 MB activation memory)!

OPT-11: Pre-Emptive Static Micro-Chunk Slicing

On e4b (42 layers), expanding a 4,000-token cache across 53 candidates at once requires 9.33 GB of contiguous memory, triggering PyTorch allocation spikes. In OPT-11, we slice candidate suffixes into fixed micro-chunks of $B_{\text{cand}} = 8$, evaluating 8 suffixes at a time (1.4 GB) and reusing the pristine base cache. Slashes API-Bank latency from 16.9s $\to$ <1.2s without memory fragmentation!

05 / Rigorous Engineering Discipline

Adversarial Audits, Real Incidents & Refuted Hypotheses

Real research isn't a straight line of triumphs. Here is the unvarnished truth of the critical bugs we caught, the crashes we debugged, and the scientific hypotheses we empirically refuted.

Incident 1 · Data Hygiene 2026-09-20

The Smoke Test Illusion & Train/Bench Pollution

The Discovery: Five independent adversarial reviews audited the codebase. They discovered that early "100.0%" scores for RAG hallucination and tool routing were evaluated on n=3 and n=7 hardcoded smoke fixtures that mirrored training templates! Worse, 218 training pairs were verbatim duplicates inside the validation split, and XNLI dev translations were leaked.

The Remediation:

Adopted a strict protocol blocking rule: Created permanent 3-way split (train / val / test, n=3,113 held-out test split, SHA-256: b34d2685f1d469db). Zero text-pair overlap was mathematically verified. All future claims required paired McNemar significance testing with 95% Wilson confidence intervals.

Incident 2 · CUDA OOM 2026-09-21

The 4.7-Hour Stage 3 Epoch-End Crash

The Crash: Stage 3 long-context training crashed with CUDA OOM after 4.7 hours of continuous training at the exact epoch boundary!
Root Cause 1: The length heuristic chars // 4 undercounted dense synthetic haystack text (citation IDs, serials) by >1.5×.
Root Cause 2: While the train loader was token-bucketed, the validation loader was unbucketed, packing 16 rows of 16K tokens (up to 262,144 tokens per eval forward!), causing an instant 4.38 GiB activation spike.

The Remediation:

Built TokenBucketBatchSampler for val and test loaders (capped at 8,192 tokens/forward). Replaced chars//4 with exact token length counting. Enabled PyTorch expandable segments and mid-epoch resume checkpointing with cryptographic fingerprint validation.

Incident 3 · VRAM Spike 2026-09-22

PEFT's Silent Vision Tower Gradient Unfreezing

The Bug: Phase 1 training OOM'd immediately on multimodal batches, even with token limits at 2,048 tokens.
Root Cause: Calling Hugging Face PEFT's from_pretrained(is_trainable=True) automatically re-enabled requires_grad=True across all base parameters—silently unfreezing the 400M-parameter SigLIP vision tower! An 8-image batch spiked VRAM by +18 GiB because it was backpropagating through 4,000 visual patches per image.

The Remediation:

Authored Gemma4ModelFrozenVision subclass enforcing torch.no_grad() at call-time on the vision tower. Memory dropped from 25.2 GiB down to 10.3 GiB with 100% visual feature fidelity.

Hypothesis Refuted · EXP-01 2026-09-28

Neutral Collapse & Refutation of "Hard Data Subsumption"

The Flawed Hypothesis: "Training primarily on hard, multi-hop reasoning data subsumes simple foundational NLI pairs, allowing us to prune SNLI/MNLI."
The Reality: In early e4b training without adversarial NLI, the model's ANLI neutral recall silently collapsed to 2.9%! In pre-registered EXP-01 (62k-row arms: 45/35/20 vs 10/65/25), Arm B (pruned) failed both gates: floor -11.7pp, medium -13.9pp, hard -5.2pp (McNemar $p \approx 0$).

The Scientific Law Adopted:

Foundational-NLI anchors are mathematically load-bearing for all difficulty tiers. A model cannot master subtle refutations if it forgets how to identify unstated neutral evidence. Permanent 15% anchor slice mandated in all future mixtures.

08 / Developer Quickstart

Python SDK, CLI & 1-Line Turnkey Fine-Tuning

Python SDK (100% Non-Autoregressive) pip install gevva 
import gevva

# 1. Load standalone champion model with auto-detected device
model = gevva.load("davidburhans/gevva-e2b", device="cuda")

# 2. Single forward-pass verification (14.3 ms P50)
probs = model.predict([
    ("Patient administered 50mg Lisinopril once daily.", 
     "Patient receives 50mg of blood pressure medication.")
])
print(probs)
# Output: [[0.012, 0.965, 0.023]]  -> Entailment verified!

# 3. High-throughput candidate reranking (Prefix KV cached)
result = model.rerank(
    premise="User requested to cancel their subscription.",
    options=["Tool: billing_cancel_plan", "Tool: weather_check", "Tool: search"],
    scoring="margin"
)
print(result.winner, result.scores)
# Output: "Tool: billing_cancel_plan" (scores: [4.21, -3.14, -2.85])
Gevva Command-Line Interface (CLI)

gevva predict \
